# `huangXuuu/loldata` 源码审计记录

参考仓库：<https://github.com/huangXuuu/loldata>

该仓库属于项目所有者，因此本项目可以复用其接口发现、字段映射和产品设计思路。

## 数据获取方面的发现

参考项目确认了官网数据域不只有排行榜接口，还包括：

- 赛季目录 `/schedule/season`
- 赛段目录 `/schedule/stage`
- 比赛列表 `/schedule/match`
- 选手英雄记录 `/compound/heroRecord`

英雄响应中包含 `pickCount`、`banCount`、`bpCount`、`winningCount` 和击杀、死亡、助攻总数，
这些计数可以支持准确的跨赛段重新计算。

参考项目使用境内 Node 代理解决 CORS 和数据域对境外云出口不稳定的问题。本项目不需要浏览器直连官网，
而是由 Spring Boot 采集端访问官网；如果部署环境无法直连，可通过 `TJSTATS_BASE_URL` 切换到受控的境内转发服务。

## 已吸收到第一阶段的设计

### 低样本过滤

参考项目使用“出场次数大于 10”筛选英雄。本项目将阈值参数化，并在数据库保留所有数据，
只在查询层过滤，防止清洗阶段永久丢失样本。

### 胜率排序必须先满足样本条件

参考项目的 BP 模拟器在按胜率排序时，只有 BP 率达到门槛的英雄才参与主要排序。
本项目第一阶段采用最低出场次数门槛，后续会增加最低 BP 率门槛和统计置信度排序。

### 版本快照差分

参考项目通过新旧累计快照相减，得到某一时间窗口内的新增统计。本项目为每次变化保存数据库快照，
后续可以直接提供版本窗口对比接口，不再依赖手工上传旧 JSON 和 Excel。

### 昂贵数据受控采集

`heroRecord` 需要按选手逐个请求，一个赛段可能产生数十次请求。为保证英雄实际分路及分路统计正确，
英雄主采集流程现已调用该接口；采集仍仅由受保护的内部接口人工触发，不会由用户查询穿透官网。
所有逐局响应都会留档，并在发布前完成局数、阵容结构和聚合计数一致性校验。

### 筛选状态与导出

参考项目支持分类筛选、数值区间、排序、列显示和“仅导出筛选结果”。本项目首个页面先实现核心赛段、
样本量和排序筛选，通用表格筛选与导出作为下一阶段前端任务。

## 后续功能候选

1. 版本窗口英雄统计：基于两个采集快照差分。
2. 队伍—英雄亲和度矩阵：英雄使用次数除以战队总局数，避免只比较绝对次数。
3. 选手同位置排名：保留分组上下文，避免跨位置直接比较。
4. 全局 BP 模拟器：支持 Bo3、Bo5 和 Fearless Draft。
5. 英雄分路趋势：基于已持久化的实际逐局分路，比较不同赛段的英雄位置变化。
6. Excel/CSV 导出：支持原始数据、统计结果和当前筛选切片。

## 相比参考项目的改进

- 请求凭据只在后端环境变量中，不暴露给浏览器或保存到浏览器存储。
- 用户请求不实时访问官网，只访问 MySQL 和 Redis。
- 跨赛段指标累计原始计数后重算，不平均百分比。
- 采集响应保存原文、哈希和运行记录，能够审计接口变化。
- 某个选择的赛段尚未采集时直接报错，不静默返回不完整数据。
- 官网瞬时连接失败时有限重试，失败后继续提供上一版数据。
